Archive DeskCLI 0.2.0 candidate

Manual project backups with Node.js 24

Back up a project folder from the terminal.

Create an Archive Desk ZIP, check the saved copy and compare a later version. Restore a checked backup into a new folder from the terminal or inspect it in the browser app.

Download CLI sourceOpen browser app

22,858-byte source ZIP. Requires Node.js 24. Tested on Windows with Node.js 24.19.0.

Four commands, one saved baseline.

Extract the source ZIP into a new folder and open a terminal there. Replace the example paths below with your own. Choose an existing output folder outside the project, and close editors that may change its files.

1

Create and verify a backup

node cli.mjs backup "C:\Projects\MyProject" --out "C:\Backups\project-new.zip"

The command reads regular project files, saves a new ZIP and verifies the bytes read back from disk. Existing output files are refused.

2

Check a saved copy again

node cli.mjs verify "C:\Backups\project-new.zip"

The check reads the ZIP records, CRC values and every manifest hash. Keep another checked copy in a separate place.

3

Compare the project later

node cli.mjs compare "C:\Backups\project-new.zip" "C:\Projects\MyProject" --report "C:\Backups\comparison-new.json"

The JSON report identifies added, removed, changed and unchanged paths. It includes the SHA-256 of the exact saved baseline ZIP.

4

Restore into a new folder

node cli.mjs restore "C:\Backups\project-new.zip" --out "C:\Recovered\project-new"

The parent folder must already exist. The destination must be new. Each restored file is written exclusively, synced and read back against its manifest. Existing destinations and linked parent paths are refused.

If a restore stops after creating the destination, its exact path is reported and partial files remain for inspection. Original timestamps, empty directories and permissions are not restored.

Recorded synthetic comparison: 1 added, 1 removed, 1 changed and 2 unchanged. Comparison leaves the project files untouched.

Recover through the browser

Open Archive Desk, choose Verify archive and select the actual saved CLI ZIP. After verification, download the recovery ZIP and inspect it in a new folder.

The CLI handles unencrypted ZIPs. The separate protection preview offers optional locked copies in its custom .adlock format.

Check what gets included.

The CLI reports skipped paths. Its default filename exclusions cover common dependency and credential names:

  • .git, node_modules and .ssh
  • .env, .env.* and credentials.json
  • Files ending in .pem, .key, .p12 or .pfx

These are filename patterns, not content-based secret detection. Review your project before sharing any backup. Symlinks, junctions and special files are refused. Empty files are retained, empty directories and permissions are not preserved.

Use a quiet source folder.

The CLI checks for source changes during scanning and reading. This is a manual capture, not an atomic filesystem snapshot. Close editors and other programs that write to the project before running it. A failed write may leave a partial new output, whose path is reported for inspection.

What was checked

Twelve CLI child-process tests passed, including five new restore cases. They cover saved-file recovery, existing destinations, corrupt and traversal archives, linked paths and preserved partial output. The unchanged archive and protection core retains its 25 prior test passes.

Python independently checked the actual saved ZIP and a five-file restore containing nested Unicode names, empty content, binary data and a UTF-8 byte-order mark. All 1,351 bytes matched. Existing files and folders survived refusal checks, corrupt and traversal archives created no destination, and a prior four-file backup also restored correctly. All six original fixture files stayed unchanged.

Independent source candidate with synthetic fixtures. Current evidence covers Windows and the current browser. Linux and macOS have not been checked. Recovery writes only to a new folder and does not provide an adversarial race guarantee. There is no installer or scheduled sync. No production security certification or customer acceptance is claimed.
