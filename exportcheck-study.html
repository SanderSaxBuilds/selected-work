Python command-line tool

Check a CSV before it goes anywhere, and keep the rows that fail.

ExportCheck checks one CSV against a small JSON rules file. Rows that pass go to clean.csv. Every rejected row goes to row-errors.csv with each reason and the full original row, so nothing disappears. Below are three recorded runs and one refusal, with the exact files they produced.

The problem

One bad row shouldn't sink the file, or vanish.

An export lands in someone else's import. A duplicate order ID, an impossible date or an amount with three decimals either breaks the import or slips through. Many checks reject the whole file, or quietly drop the bad rows and leave no record of what went missing.

ExportCheck splits the file instead and writes a summary.json with the counts. Formula-like text such as =SUM(1,2) gets an apostrophe in the clean file so it can't run in a spreadsheet.

Exit codes

  • 0Every row passedClean file, empty error file, summary.
  • 1Some rows were rejectedThe good rows still go through. The rest are listed with reasons.
  • 2The file itself is unusableFor example duplicate headers. No result folder is created.
  • 3The output folder already existsEarlier results are never overwritten.

Overwrite refusal

Run it twice and the first results stay put.

After the clean run created its result folder, I pointed ExportCheck at the same folder again. It refused with exit code 3. The three result files had the same paths, sizes and SHA-256 hashes before and after.

Where this stops

These are saved results from ExportCheck 1.0.0 on synthetic sample files. The page doesn't run the tool or accept your file, and the tool has no customer use yet.

  • The output only reflects the sample rules shown in the Rules tab.
  • Amounts are checked as exact decimals within a range. It doesn't infer currency or reconcile totals.
  • It doesn't repair rows or connect to an ERP.

What it needs

Python 3.10 or newer and nothing else. The standard library covers the CSV reading, decimal checks and file writing.
