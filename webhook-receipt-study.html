Where this proof stops

  • One fictional event namespace and one local database.
  • Fresh in-memory signing key on each service start.
  • Five-minute delivery timestamp window.
  • No guarantee for exactly-once external actions.
  • No provider integration or production deployment claim.

A practical first repair

For a real duplicate-callback issue, first reproduce the failure from an anonymized event and the receiving code. Agree the event ID contract, retry window, ordering rule and acceptance checks before changing storage or connecting external actions.

This independent sample demonstrates a repair approach. It is not a customer case study or a production service.
