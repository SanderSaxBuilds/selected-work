Python document parsing

Word procedures into steps you can trace back.

Work instructions usually live in Word. This parser reads one written to a set template and writes the title, safety notes and steps to JSON and CSV. Every value keeps the number of the paragraph it came from and the hash of the source file. Anything outside the template stops the run instead of being guessed at.

Refusals

When the input is wrong, nothing is written.

A parser that skips what it doesn't understand hands someone an instruction with a missing step. This one stops and says why.

Step numbering

No gaps, no repeats

Steps must start at 1 and run in order. A document that jumps from Step 1 to Step 3 is rejected.

ERROR[TEMPLATE_STEP_SEQUENCE]: Expected Step 2, found Step 3.
Unsupported content

Tables and lists are refused

Tables, images, automatic Word numbering, macros and embedded objects stop the run instead of being dropped quietly. So do unlabeled paragraphs.

ERROR[UNSUPPORTED_TABLE]: Tables are not supported by this preview.
Existing files

No overwrite on a rerun

Writing to a folder that already has the outputs returns an error and leaves both files as they were. This is the actual message from the rerun.

ERROR[OUTPUT_EXISTS]: Refusing to overwrite existing output: work_instruction_preview.json, work_instruction_preview.csv.

The code that matters

Safe in a spreadsheet, exact in JSON.

Step text that starts with =, +, - or @ would run as a formula when the CSV opens in Excel. The CSV gets a leading apostrophe. The JSON keeps the original text, so nothing is lost.

The parser reads the DOCX package directly with the Python standard library and checks the ZIP before it opens anything: 8 MiB compressed, 4 MiB per member and 16 MiB expanded at most.

Where this stops

This is an extraction building block tested on a fictional document. It reads one labeled template, not any Word file. The test document is generated in code and hasn't been opened in Word itself.

  • Supported: one title, optional safety notes before the steps, then consecutive steps of one paragraph each.
  • Not supported: other layouts, tables, automatic lists, headers and footers.
  • No upload, MES connection or production deployment.

How a real project would start

With an anonymized copy of one of your real documents. We'd agree which structure the parser accepts and how each field maps to your system, then test against a set of known documents before connecting anything.
