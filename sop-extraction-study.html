From a labeled Word document to traceable steps.

A small Python parser turns an explicit work-instruction template into JSON and CSV. Every extracted field keeps its paragraph reference, so the result can be checked against the source.

This page presents a recorded local run. It does not process uploads. The parser supports the labeled paragraph template below, not arbitrary Word documents or a manufacturing-system integration.

02 / Refusal and preservation checks

An unsupported input stops the run.

REFUSE BEFORE OUTPUT

No guessed steps

Labels must start at Step 1 and stay consecutive. Tables, images, automatic numbering and unsupported body content are rejected rather than silently dropped.

Step 1 → Step 3: rejected

RAW TEXT RETAINED

Literal CSV values

Formula-like text gets an apostrophe in CSV. JSON keeps the original value. Unicode, leading zeros and quoted text are checked separately.

=2+2 → '=2+2 in CSV

EXISTING FILES PRESERVED

No overwrite on rerun

A second CLI run to the same output folder returns an error. The independent check confirmed both earlier outputs and the input remained unchanged.

ERROR[OUTPUT_EXISTS]

Where this proof stops

This is an extraction building block. The next project step would be to review an anonymized real document and agree its supported structure and output mapping.

The recorded checks establish template parsing and file behavior. They do not establish customer acceptance, production performance or native Word rendering.

Supported now

  • One manually labeled title, optional safety paragraph and sequential steps.
  • Source SHA-256 and paragraph references in both output formats.
  • Checks for unsafe ZIP members, excessive expansion and unsupported content.

Separate work would be required

  • Arbitrary SOP layouts, tables and automatic Word lists.
  • Approved manufacturing fields, API mapping and a test environment.
  • Any ION MES connection, upload or production deployment.
