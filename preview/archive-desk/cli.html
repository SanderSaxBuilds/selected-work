Archive Desk for the terminal

Back up a project folder from the terminal.

Create an Archive Desk ZIP, check the saved copy and compare a later version of the folder. Restore a checked backup into a new folder, or open it in the browser app.

Download the command line sourceOpen the browser app

Needs Node.js 24 and nothing else. Tested on Windows with Node.js 24.19.0.

Four commands, one saved baseline

Extract the source into a new folder and open a terminal in its ArchiveDeskCLI folder. Type your own folders below and the four commands are rewritten to match. Pick an existing output folder outside the project and close editors that might change its files.

Showing the example paths.

  1. 1

    Create and verify a backup

    node cli.mjs backup "C:\Projects\MyProject" --out "C:\Backups\project-new.zip"

    Reads the regular project files, saves a new ZIP and verifies the bytes it reads back from disk. An existing output file is refused.

  2. 2

    Check a saved copy again

    node cli.mjs verify "C:\Backups\project-new.zip"

    Reads the ZIP records, CRC values and every manifest fingerprint. Keep another checked copy somewhere else.

  3. 3

    Compare the project later

    node cli.mjs compare "C:\Backups\project-new.zip" "C:\Projects\MyProject" --report "C:\Backups\project-new-comparison.json"

    The JSON report lists added, removed, changed and unchanged paths, plus the SHA-256 of the exact backup it compared against.

  4. 4

    Restore into a new folder

    node cli.mjs restore "C:\Backups\project-new.zip" --out "C:\Recovered\project-new"

    The parent folder must exist and the destination must be new. Each file is written, synced and read back against the manifest. Existing destinations and linked parent paths are refused.

    If a restore stops partway, the command reports the exact folder and leaves the partial files there for you to inspect. Timestamps, empty folders and permissions are not restored.

In the sample comparison: 1 added, 1 removed, 1 changed and 2 unchanged. The project files stayed untouched.

Recover in the browser

Open Archive Desk, choose Verify and pick the ZIP the command saved. Once it passes, download the recovery ZIP and extract it into a new folder.

The command line makes unencrypted ZIPs. For a locked copy, use the encrypted copies preview.

Check what gets included

The command lists every skipped path. By default it leaves out common dependency and credential names:

  • .git, node_modules and .ssh
  • .env, .env.* and credentials.json
  • Files ending in .pem, .key, .p12 or .pfx

These are filename patterns, not a scan of file contents, so review the project before you share a backup. Symlinks, junctions and special files are refused. Empty files are kept. Empty folders and permissions are not.

The command watches for changes while it scans and reads, but it is a manual capture, not an atomic snapshot. Close anything that writes to the project before you run it.

What has been checked

  • Twelve command tests pass, five of them for restore: saved-file recovery, existing destinations, corrupt and path-traversal archives, linked paths and kept partial output.
  • A separate script checked a five-file restore with nested Unicode names, an empty file, binary data and a UTF-8 byte-order mark. All 1,351 bytes matched.
  • Refused restores left existing files and folders alone, and corrupt or traversal archives created no destination.

Tested on Windows only. Linux and macOS have not been checked. There is no installer or scheduled sync.
