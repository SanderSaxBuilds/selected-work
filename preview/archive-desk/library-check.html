Workbench guide

Check every saved copy.

Reread your backup library before you need it. See which archives still match their records, which copies have failed and what needs your attention.

Download for Windows x64How to start
  1. 01

    Read the saved bytes again.

    Every archive is checked against its recorded fingerprint, ZIP structure and file manifest. Copies are checked one after another, so a large library takes a while.

  2. 02

    Keep failed copies visible.

    A missing file, a damaged ZIP or a record mismatch each gets its own failed row, and the rest are still checked. Nothing is repaired or removed behind your back.

  3. 03

    Download the dated result.

    The JSON holds the same passes and failures you see on screen. Refreshing or changing the library clears the report before the next check.

Try it

  1. Start the app. The overview shows how.
  2. Create a backup or import an existing Archive Desk ZIP.
  3. Select Check every backup below the saved library.
  4. Read the totals and every failed row. Download this report saves the same result as JSON. A check never starts a repair or a recovery.

Reading the result

Each row shows the backup label, the recorded fingerprint, the fingerprint read during this check when there is one, a status and the reason for any failure. Passing rows add file counts and total size. An empty library reports zero checked, never a pass.

Earlier verification dates stay as they were. The view keeps the recorded history apart from this fresh check, and a failed copy is marked Check failed.

The report leaves out absolute workspace and storage paths. Labels can still identify your work, so read it before you share it.

Recovery stays separate

Recovery still runs through its own reviewed plan, which checks a new destination and the file list before you confirm.

  • Unencrypted Archive Desk ZIPs only.
  • Up to 500 files, 20 MiB per file, 50 MiB of source data and a 52 MiB ZIP.
  • Manual checks only, with no schedule or cloud sync.
