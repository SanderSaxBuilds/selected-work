    Layer 3, the code

    Decide inside the transaction.

    Check, insert and update run under BEGIN IMMEDIATE. 24 copies at once: 1 recorded, 23 duplicates.

    The digest. Sorted keys, no spaces, then hashed. New spacing is the same event, a new value is not.

    The ordering rule. An older event gets its own receipt, the shipment keeps the newest status.

    • stale and future timestamps
    • unknown fields
    • duplicate JSON keys
    • invalid UTF-8
    • deep nesting
    • oversized bodies
    • cross-origin
    • unexpected hosts

    Where this stops

    A study with fictional shipments, not a production service.

    • One event namespace and one local SQLite database.
    • A new signing key is generated each time the service starts.
    • The five-minute window and the ordering rule are study choices.
    • No exactly-once side effects, no provider connection.

    How a real repair would start

    Reproduce the failure from an anonymized event first. Then agree the ID contract, retry window and ordering rule, before touching storage.
