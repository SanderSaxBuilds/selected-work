Workbench guide

Check the plan. Then recover.

See the saved files, their fingerprints and the destination before a single recovered file is written. Download a fresh verification report without touching your library.

Download for Windows x64How to start
  1. 01

    See what will come back.

    Pick a new folder name. The plan checks the saved ZIP, lists each file with its size and SHA-256 and confirms the destination is unused.

  2. 02

    Recover the checked copy.

    A separate button starts the recovery. Changing the folder name clears the plan, and recovery checks the archive again before it writes.

  3. 03

    Download a fresh report.

    The JSON report rechecks the archive and lists every relative path and fingerprint. A damaged archive gives an error, never a passing report.

Try it

  1. Start the app. The overview shows how.
  2. Create a backup or import an existing Archive Desk ZIP.
  3. Select Review recovery, enter a new folder name and choose Check recovery plan.
  4. Read the destination and file list, then choose Restore checked copy. Download the verification JSON from the selected backup when you need a report.

What the report holds

Its check time, backup label, archive fingerprint, file counts and the relative path, size and SHA-256 of every file. Exporting it leaves the saved verification time and activity log alone.

Absolute workspace and storage paths are left out. Labels and file names can still identify your work, so read the report before you share it. A matching fingerprint shows the archive is consistent with its record. It does not prove who made it or that the contents are safe.

A plan is a snapshot of one moment. It does not reserve the folder or stop another program from changing files between checks.

Which archives work

  • Unencrypted Archive Desk backups, such as those from the browser app or the command line.
  • Up to 500 files, 20 MiB per file, 50 MiB of file data and a 52 MiB ZIP.
  • Not compressed ZIPs from other apps, encrypted .adlock files or ZIP64.
  • Paths and bytes are restored. Empty folders, timestamps and permissions are not.
